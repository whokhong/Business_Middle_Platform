## 二、文档 A · 全局 UI 规范（章节结构，不可增删）

```
§0 文档信息（版本/依据/适用范围/读者）
§1 设计目标与原则          —— 承接 UIUX §1.1/§1.3，补可度量口径
§2 设计 Token 全量清单 ⭐  —— 核心章
   §2.1 色彩（画布/区块/文字/线条/品牌/语义/渠道，含「品牌红 vs danger」强制规则 5 条）
   §2.2 字体排版（字号阶梯 + 字距硬规则：唯一正字距=徽标 +0.125px）
   §2.3 间距与栅格（4px 阶梯 / 24 栅格 / v2 三栏为三个独立栅格容器）
   §2.4 圆角与阴影（Notion 多层低透明度；静止靠边框、悬浮加淡影）
   §2.5 动效（≤200ms ease-out / 尊重 prefers-reduced-motion）
   §2.6 图标（20px 网格线性 / 管理端 16px / 禁用混风格）
   §2.7 层级 z-index（内容 < 行动栏 z30 < Tab 栏 z40 < 抽屉 z60 < Toast）
   §2.8 断点与响应式
   §2.9 【落地表】Token → CSS 变量 → 实际值 → 用途 四列表（供前端直接抄）
§3 全局状态规范 ⭐         —— 加载/空/错误/无权限/网络异常/会话过期 六态，每态给「视觉 + 文案 + 触发条件 + 恢复路径」
§4 组件规范 ⭐             —— L0(Element Plus 注入主题) / L1(自研 12 个，逐个给 API+props+events+状态+无障碍) / L2(卡片物料)
§5 反馈与确认规范          —— Message/Notification/Dialog/Drawer/行内反馈 使用边界 + 时长；高危操作 HighRiskConfirm 规范
§6 表单与表格规范          —— 标签对齐/校验时机/错误文案；分页/排序/筛选折叠/列设置/批量/时间与数字格式
§7 权限的界面表达          —— v-perm 四策略（按钮/菜单/页面/数据）+ 隐藏 vs 禁用+tooltip 的判定标准
§8 可访问性规范            —— 对比度/键盘/焦点/动效/语义化
§9 文案与国际化            —— 动词开头/错误提示含原因+解法/时间格式/i18n key 约定
§10 命名与交付规范         —— Figma 命名 / 文件命名 / 组件命名 Bmp 前缀 / 设计走查清单
附 A 与 PRD/UIUX 的追溯矩阵（本章每条规则 → 依据的 PRD 需求编号 / UIUX 章节）
```

**A 文档硬要求**
1. §2.9 的四列表**必须逐 Token 列全**（含 `--bmp-*` 兼容别名轨），前端可零歧义落地；
2. §2.1 必须写明「**紧急/超时 = 品牌红 `#C8161D`；错误/失败 = danger `#F53F3F`**」，并给出**反例**（当前原型 `todos.html:20` 错误用法）；
3. §3 六态必须给**可直接抄的文案模板**（如空态必带下一步动作）；
4. §4 L1 组件必须与 UIUX §7.2 的 12 个组件**一一对应且不遗漏**；
5. 每章末尾给「**走查 checklist**」（可勾选项），供后续验证脚本/人工走查复用。

## 三、文档 B · UI/UX 页面规范（逐页模板，8 要素，不可增删）

> 每页**一套 8 要素**，编号与 UIUX 页面 ID 严格一致（如 `UI-A1-01`）。管理端页面按 `UI-C-xx`。

```
### {页面ID} {页面名}  （端：门户/移动/管理·登录 ｜ 优先级 P0/P1/P2 ｜ 版本 V1.0/V1.5）

| 项目 | 内容 |
| 路由 | /xxx（原型文件或 console.html?page=xxx） |
| 对应 PRD 功能点 | A1-F01（+ 子点）；**主责点在前，关联点在后** |
| 上游页面 | 从哪进入 |
| 下游页面 | 出到哪（跳转/抽屉/新标签） |

① **页面结构（区块树）** —— 缩进树形，每个区块标 `[组件]` 与可见条件
② **字段与数据** —— 表格：字段名 / 类型 / 来源（API 或 来源字段）/ 校验 / 是否必填 / 展示格式
③ **交互与操作逻辑** —— 逐条编号写：「触发 → 行为 → 状态变化 → 反馈」；含校验拦截、去重、上限、二次确认
④ **权限与可见性** —— 哪些按钮/区块对哪些角色可见/隐藏/禁用（v-perm 权限码）
⑤ **5 态设计** —— 加载/空/错误/无权限 + （如涉及）网络异常/会话过期：每态给视觉与文案
⑥ **边界与异常** —— 极值、并发、超时、降级、数据缺失、长文本、空数据、权限不足降级
⑦ **跳转关系图** —— 文本流程图（A→B 条件）
⑧ **验收清单** —— 可勾选项，逐条对应 ③④⑤⑥；含「对照 PRD 功能点的验收断言」
```

**B 文档硬要求**
1. **每页必须能追溯到 PRD 功能点编号**；若某页在 PRD 中**无对应功能点**，必须显式标注 `⚠ PRD 无对应功能点，属原型越界或 UI 细化`；
2. **反向也必须做**：文档 B 末尾附「**PRD 前端可见功能点 → 页面**」映射表，**凡 PRD 有但无页面承载的功能点必须列出**（这是"100% 还原"的判据）；
3. ③ 交互必须写到**可被开发直接实现**的粒度（如「连续失败 3 次后追加图片验证码」而非「有验证码」）；
4. 必须与原型**逐一比对**——发现「原型有但规范没写」或「规范写了但原型没做」的，**在文档 B 末尾「⑦ 章节」列差异清单**（这直接成为修复输入）；
5. 管理端页面遵循 UIUX §4.1 五范式（列表页/左树右表/详情抽屉/向导/工作台），每页标注归属范式。

## 四、核查报告（`outputs/核查/`，独立交付）

### 4.1 `01-原型可交互性核查.md`

| 维度 | 检查方法（须给证据行号） |
| --- | --- |
| 语法与运行 | `node --check` 全部 JS；是否存在运行时必然报错的引用 |
| DOM 完整性 | `getElementById`/`querySelector('#…')` 与 `id="…"` 求差集 |
| 事件绑定 | `on*=` handler 是否有定义；事件是否重复绑定/泄漏 |
| 路由与死链 | 所有 `href` 目标文件是否存在；`?page=` 键是否都在 `CONSOLE_MENU`/`PAGES` |
| 状态流转 | 关键交互（登录跳转/视图切换/编辑模式/向导分步/批量/去重）是否能走通 |
| 零依赖 | 无 CDN/外链字体/构建产物 |
| 持久化 | localStorage 键读写是否成对、异常是否兜底 |

### 4.2 `02-PRD还原度核查.md`

| 维度 | 说明 |
| --- | --- |
| **覆盖率** | PRD 前端可见功能点 × 原型实体（页面/区块/交互）双向矩阵；给「已还原 / 部分还原 / 未还原」三态 |
| **操作逻辑** | 逐页比对 PRD §6「操作流程」要素 vs 原型实际行为；列出逻辑缺失/错误 |
| **交互** | 校验、去重、上限、二次确认、降级链是否实现 |
| **页面展示** | 字段、列、标签、文案、状态标签颜色是否与 PRD/UIUX 一致 |
| **Token 一致性** | 硬编码色值/字号/间距清单；是否有冷色残留；语义色是否误用 |
| **5 态覆盖** | 每页态覆盖矩阵 |

**问题清单格式（强制）**

| ID | 级别 | 页面 | 问题 | 证据（文件:行号） | 违反依据 | 修复建议 | 预估影响 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| R-01 | P0/P1/P2 | UI-xx | …… | `todos.html:20` | UIUX §2.1-3 | …… | …… |

**级别判定**
- **P0**：导致功能不可用 / 违反用户已拍板决议 / 语义色误用（红色告警失效）；
- **P1**：违反 UIUX 明确规则（Token/状态/文案/权限）；交互逻辑与 PRD 不符；
- **P2**：体验瑕疵、可访问性改进、非阻塞一致性问题。
