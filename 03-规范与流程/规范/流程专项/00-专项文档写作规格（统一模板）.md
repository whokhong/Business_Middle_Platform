## 二、统一章节模板（**7 部分，缺一不可**）

每份文档**必须包含以下 7 个一级章节**，顺序不得调整。各章节的要求如下：

### §0 文档说明（≤15 行）
- **覆盖范围**：本流程覆盖哪些功能点（列编号 + 名称 + 版本）
- **不在范围内**：明确排除项（防读者误以为涵盖）
- **真源索引**：本流程对应的 PRD 章节（§号）、详细设计章节、UIUX 页面 ID
- **术语表**（若有本流程特有术语，≤6 条）

### §1 产品价值（**必须回答「为什么做」**）
| 小节 | 要求 |
| --- | --- |
| 1.1 业务痛点 | **≥3 条**。每条须写「现状 → 后果」（如「5 套系统各自建号 → 人员离职后权限残留」），**不得写空话** |
| 1.2 价值主张 | 本流程解决什么、对谁有价值。**须区分三类角色**：业务用户 / 研发（接入方）/ 运维与管理员 |
| 1.3 量化收益 | 引用 PRD §1.4 北极星指标（区分「已有指标」与「本流程直接贡献的指标」）；**无指标的写「定性收益」并说明为何无法量化** |
| 1.4 不做会怎样 | ⚠️ **量化风险**（如「不做 → 全员权限清空」「不做 → SSRF 断链」）。**引用 PRD 已有的风险表述，附行号** |

### §2 用户故事（**必须可验收**）
- **格式**：`作为 <角色>，我希望 <做什么>，以便 <获得什么价值>`
- **数量**：**≥6 条**，且**必须覆盖**：① 主流程（Happy Path）；② 管理员/配置者视角（≥2 条）；③ 异常/边界场景（≥2 条）
- **每条附**：`验收标准`（Given-When-Then 或可判定的检查项）+ `关联功能点编号`
- **禁止**：只写"用户希望系统好用"这类不可验收的描述

### §3 业务流程（**必须可视化 + 可执行**）
| 小节 | 要求 |
| --- | --- |
| 3.1 主流程 | **必须含 mermaid 图**（flowchart 或 sequenceDiagram），**图中节点须标注承载功能点编号**（如 `I1-F01`） |
| 3.2 角色与职责 | 表格：`角色 | 在本流程中的动作 | 涉及界面/接口` |
| 3.3 分步说明 | 按步骤编号，每步写：`触发条件` / `执行动作` / `关键规则`（引用 BR 编号）/ `异常分支` |
| 3.4 异常与边界 | **≥4 条**异常场景，每条写：`场景` / `系统行为` / `用户可见结果` / `是否阻断` |
| 3.5 版本归属 | 表格：`步骤 | 功能点 | 版本(V1.0/V1.5/...)| 说明`；**版本必须与 PRD 一致** |

### §4 数据流（**必须落到表/接口**）
| 小节 | 要求 |
| --- | --- |
| 4.1 数据流图 | **mermaid 图**（flowchart LR 或 sequenceDiagram），标注 `表名` 与 `接口路径` |
| 4.2 数据实体清单 | 表格：`实体/表名 | 所属库 | 用途 | 读/写 | 关联功能点` |
| 4.3 接口清单 | 表格：`接口 | 方法 | 用途 | 调用方 | 详细设计章节`；**路径须与详细设计一致** |
| 4.4 关键字段与约束 | 只列**本流程关键**的字段（UK / NULL 语义 / 枚举值），**不得全量抄表** |
| 4.5 数据生命周期 | 数据的产生 → 流转 → 归档/失效；涉幂等键的**须写明** |

### §5 技术逻辑方案（**必须解决问题，不只是描述**）
| 小节 | 要求 |
| --- | --- |
| 5.1 架构落点 | 涉及服务（`bmp-server-*`）/ 库（`bmp_*`）/ 连接器；**引用详细设计 §2 工程结构** |
| 5.2 关键机制 | 本流程的**核心技术机制**（如幂等、事务边界、重试、降级、缓存、并发控制）。**每条须写「机制 → 解决什么问题 → 不这么做会怎样」** |
| 5.3 时序/状态机 | 若有状态机，**必须画状态图并列出状态枚举**；若有复杂时序，**画时序图** |
| 5.4 性能与容量 | 引用 PRD 已有的性能要求（如「P95 <2s」「≤10 分钟同步」）；**无要求的写「待定」并标注** |
| 5.5 安全与合规 | 鉴权、审计留痕、敏感数据处理（如 secret 掩码、AES 加密）、防注入 |
| 5.6 已知限制与技术债 | 如实写（含「建议新增，待实施确认」项）；**不得粉饰** |

### §6 验收与度量（**必须可测**）
| 小节 | 要求 |
| --- | --- |
| 6.1 功能验收清单 | 表格：`# | 验收项 | 判据 | 优先级(P0/P1/P2)| 关联功能点`，**≥10 条** |
| 6.2 端到端验证场景 | **≥3 个**完整场景（从入口到出口），每个写清「前置条件 → 操作 → 期望结果」 |
| 6.3 度量指标 | 表格：`指标 | 目标值 | 采集方式 | 归属功能点` |
| 6.4 回归红线 | **≥3 条**「绝对不能破坏」的约束（如「secret 不得出现明文」「未映射不静默丢弃」） |

### §7 附录
- **7.1 关联文档索引**：PRD §号 / 详细设计 §号 / UIUX 页面 ID / 原型页面 key
- **7.2 原型操作路径**：`console.html?page=xxx` → 哪个菜单 → 哪个 Tab → 点击哪个按钮
- **7.3 未决问题**：如实列出（含 owner 建议）

## 三、统一写作口径（**5 条硬约束**）

| # | 约束 | 说明 |
| --- | --- | --- |
| **1** | **禁止臆造** | 所有事实性结论（表名、接口、编号、版本、指标值）**必须可在 PRD / 详细设计 / UIUX 中查到**；引用时**附 `file:行号`**；查不到就写「未找到」+ 检索命令 |
| **2** | **保守标注** | 「建议新增，待实施确认」的项（如 `sys_org_mapping` / `sys_permission_migration` / `domain_whitelist`）**必须保留该标注**，不得写成既定事实 |
| **3** | **版本准确** | 版本归属**严格照抄 PRD**（特别注意：`B2-F03` 数据权限 = **V1.5**；`J2-F05` = **V1.5**；`I1-F01` 完整版 = V2.0 但有 V1.0 简版） |
| **4** | **引用行号带时点声明** | PRD 行号会随编辑漂移 → **引用格式统一为**：`PRD §X.Y（关键词）` 为主、行号为辅；若必须给行号，**同时给内容关键词** |
| **5** | **不得复制粘贴大段原文** | 本套文档是**视图层**，应**提炼与重组**；直接照抄超过 10 行的原文段落视为不合格 |
