# 首页重构 · 设计方向简报（主理人综合）

> 用户选定 **Notion·Claude 暖色极简风**，要求首页（PC + 移动）**打破现有结构与思维**，明确指出「现有效果图很传统和保守」。
> 本简报是主理人对现状的诊断与重构方向的裁定，供产品经理细化为规格、工程师实现。**方向不可偏离**。
>
> **V1.5 实施裁定（2026-10-21）**：以 PRD **方案 A** 为准 — **产品不交付 B7 多轮助手**（默认 **关闭**、可配置演示项）；**原型** `home-v2` / `mobile/home-v2` **恢复右下角 FAB + mock 对话** 便于演示完整体验。左栏「今日简报」仍为 **规则引擎**（cardId `ai-brief`），**无**生产 Prompt 管理台；智能入口走 **⌘K + 意图项**（`portal-apps&tab=intents`）。助手演示配置：`console.html?page=portal-ai-assistant`（`bmp_portal_ai_config`）。**关注动态**（`watch-list`）V1.5 **仅**在 **布局模板** 控制显隐；动态内容与关注关系 **无运营后台**（V2.0 再议 feed API）。

## 一、现状诊断：为什么"传统和保守"

### PC 首页（`prototype/home.html`）三大症结

| 症结 | 具体表现 | 本质问题 |
|---|---|---|
| **① 答案是"罗列"而非"判断"** | 红色问候横幅 → 24 栅格卡片大盘（待办 / 常用应用 / 消息公告 / 数据指标），四张卡平铺 | 首页**没有观点**。它把原料（待办、消息、应用）摆出来让用户自己判断，而用户要的是"我现在该做什么" |
| **② 入口是"导航"而非"意图"** | 应用宫格 8 个图标，先想"去哪个系统"再点进去找事做 | 认知成本前置。用户脑子里的问题是"我要请假"而不是"我要打开 OA" |
| **③ 布局是"均匀栅格"而非"视觉权重"** | 所有卡片同尺寸同权重（grid 6/8/12/16/24 只是宽度调节） | 眼睛没有落点。真正紧急的事（1 小时后超时）和可有可无的事（数据指标）视觉权重相同 |

### 移动端首页（`prototype/mobile/index.html` 屏 1）症结

- 结构 = 渐变问候卡 → 金刚区 4 图标 → 紧急待办列表 → 常用应用宫格
- 这是**2018 年的企业门户范式**（"金刚区 + 宫格"），移动端变成了 PC 首页的缩小版，**没有利用移动端"随身、即时、拇指操作"的特性**
- 顶部渐变横幅占掉大量首屏空间，用户看不到"最要紧的那件事"

## 二、重构方向：三个范式转变（核心裁定）

### 转变 ①：从「数据罗列」→「AI 判断」

**首页首屏不再是卡片墙，而是 AI 生成的「今日简报」（Morning Brief）。**

- 用**自然语言**说出今天的重点，并**直接给行动**：
  > 「早上好，张三。今天有 **2 件事要先处理**：
  > **华宇科技的合同审批** 今天下午 3 点前要过（还剩 4 小时），
  > **李四的入职 offer** 已等你 2 天。
  > 其余 4 件可以晚点看。」
- 简报下方直接挂「立即处理」主按钮 + 「看全部」
- **这是从"展示数据"到"给建议"的根本转变**——首页承担"判断"职责，而非只做"展示"

### 转变 ②：从「应用导航」→「意图流」

**去掉传统应用宫格作为主入口，改为「意图流」（Intent Stream）。**

- 按"你要做什么"组织，而非"去哪个系统"：
  - `发起一个审批` · `查我的合同` · `找人` · `看本月数据` · `我要请假` · `提个报销`
- 意图项点击后：中台自建流程 → 直接在当前页拉起表单；外部系统 → 带 SSO 直达对应页面（不再浪费一次跳转）
- **保留「全部应用」入口但降级**为次级入口（意图流覆盖不到的角落需求）

### 转变 ③：从「均匀栅格」→「时间轴 + 视觉权重」

**以「时间紧迫度」为组织主轴，而非以「卡片类型」。**

- 主轴是一条**纵向时间轴/流（Stream）**，按紧迫度排序：
  - 今天必须做（红）→ 本周待办（黄）→ 知悉即可（灰）
- 视觉权重随紧迫度衰减：紧急项大而醒目、知悉项小而克制
- 打破"卡片=容器"的思维——改为**流式行项目**（Notion 的 database/row 气质），而非一堆方块

## 三、PC 与移动端的分工（不做缩小版，各自扬长）

| 维度 | PC 端（横向空间大、键盘、多任务） | 移动端（随身、拇指、即时） |
|---|---|---|
| **首屏核心** | 今日简报（完整版）+ 意图流 | 今日简报（精简 1-2 句）+ **最紧急那一件事的大卡** |
| **主入口** | **⌘K 命令栏**（键盘优先，一句话直达） | **AI 对话入口**（拇指可达，语音/文字） |
| **组织方式** | 三栏：左侧今日简报与意图流 / 中间时间轴流 / 右侧关注与动态 | 单列纵向流，**首屏就要看到"最要紧的事"** |
| **交互特色** | 键盘优先、悬浮预览、可拖拽调整流顺序 | 手势：下拉唤起 AI、左右滑处理待办、底部固定行动栏 |
| **空间利用** | 利用横向空间做"并列信息"（时间轴 + 侧栏） | 不允许顶部大横幅占位；内容即刻可见 |

**共同点**：都**必须首屏回答"我现在最该做什么"**。

## 四、AI 融入（用户已确认的两项，落在首页）

1. **今日简报**（AI 生成摘要 + 优先级判断）→ 落在首屏
2. **意图流 + 智能填单** → 点击意图项后，AI 预填表单（如"我要请假"→ 自动填好日期、部门、剩余年假），用户只需确认

补充（本方案增补，属自然延伸）：
3. **AI 对话入口**（移动端为主入口、PC 端为 ⌘K 命令栏 + 助手浮层）

## 五、必须守住的既有约束（不可推翻）

| 约束 | 说明 |
|---|---|
| **布局引擎必须保留** | 既有 `layoutTemplate`（template_json 角色模板 + user_override 个人覆盖）+ `cardManifest` 注册机制是 V1.0 功能点（A1-F02 布局引擎），**不能因为重构就删掉**。重构后应是"新首页作为默认模板"，编辑模式与卡片注册机制继续可用 |
| **卡片注册机制** | 新首页的区块（简报/意图流/时间轴）应以**新的 cardId 注册进 manifest**，保持"新卡片=注册 manifest，零平台改造"的架构承诺 |
| **权限过滤** | 无权限的应用与内容不展示（既有 G4 规则） |
| **技术约束** | 纯 HTML/CSS/JS 单文件、内联样式、零依赖、系统字体、真实可交互 |
| **Notion 风格参数** | 暖白 `#f6f5f4`（带黄褐底调）/ 正文 `rgba(0,0,0,.95)` / 次要 `#615d59` / 弱 `#a39e98` / `1px solid rgba(0,0,0,.1)` 细边框 / 多层低透明度阴影（累计 ≤0.05）/ 标题 48px/700/字距 -1.5px / 正文 16px/400/行高 1.5 / 徽标 12px/600/**+0.125px** / 麓邦红 `#C8161D` 作强调（可配暖橙 `#dd5b00`）/ 胶囊 9999px |

## 七、判断标准（用于验收）

重构后的首页，**必须能通过这三个检验**：

1. **三秒检验**：用户打开首页 3 秒内，能说出"我今天最该做的第一件事是什么"
2. **一句话检验**：用户能用一句话（而非点击 3 层菜单）到达目标动作
3. **权重检验**：最紧急的事与最不重要的事，视觉权重明显不同（不是一样大的卡片）

若仍做不到这三条，说明还停留在"传统门户"范式内。
