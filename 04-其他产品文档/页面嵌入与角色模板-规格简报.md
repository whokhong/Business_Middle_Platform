# 首页「任意页面嵌入」+「管理员按角色配模板」· 规格简报（主理人）

> 用户需求原话：「是要**任意页面**，那这样的话方案B就不合适吧；也需要"**管理员配模板**"，对不同的角色可以配置；**可以直接做原型验证**」
> 本简报固化现状事实、主理人裁定与实现规格，供工程师执行。**不得偏离。**

---

## 一、为什么放弃方案 B

上一轮我推荐「Path B：应用供给卡片」（应用按卡片协议提供数据接口，中台渲染）。**用户明确要"任意页面"，B 的前提不成立**：

| | 方案 B 的前提 | 用户要的「任意页面」 |
|---|---|---|
| 接入要求 | **每个应用都要开发数据接口** | 页面**已经存在**，不应要求改造 |
| 适用范围 | 只能接"愿意配合改造"的应用 | 任意页面（驾驶舱/大屏/报表/第三方系统） |
| 结论 | —— | **B 不适用，必须走内嵌路线** |

**因此本次采用「内嵌页面卡片」+「管理员按角色配模板」两条腿。**

## 二、核心障碍与主理人裁定（关键）

### 障碍：UIUX 决议 #5
> **决议 #5**：存量系统跳转 —— **新标签页**（避免 iframe 会话冲突），**不用内嵌**。

### 主理人裁定：**不推翻 #5，新增 #5b 区分场景**

两条决议管理的是**两个不同场景**，并不矛盾：

| 决议 | 场景 | 用户行为 | 结论 |
|---|---|---|---|
| **#5（保留）** | **应用跳转** | 点应用图标 → 去那个系统干活 | **仍用新标签页**，不改 |
| **#5b（新增）** | **页面驻留** | 把某个页面**长期放在首页**看（大屏/驾驶舱） | **允许受控内嵌（iframe）** |

**为什么 #5 的顾虑在 #5b 下可以解决**：
- #5 担心的是「**iframe 会话冲突**」（iframe 内无法共享中台登录态，导致要二次登录或串号）；
- **中台已有现成机制**：`POST /v1/auth/ticket/exchange`（一次性 ticket 换标准令牌，5min TTL、one-time）——这正是为"老系统适配"设计的；
- #5b 下的嵌入页面通过 **ticket 交换**获得会话，不共享 Cookie，**不产生会话冲突**。

**#5b 的附加约束（必须实现，防止滥用）**：
1. **必须走白名单**：只有 `I1 应用注册`中登记过的域名/URL 才允许嵌入（防钓鱼、防越权）
2. **必须有降级**：加载失败/超时/被目标页拒绝（`X-Frame-Options`）时，显示友好降级（标题+「在新标签页打开」按钮），**不留白屏**
3. **必须有加载态**：嵌入页加载中显示骨架/loading，不要让用户看到空白
4. **不改变 #5**：应用**图标点击**（应用中心、我的订阅、意图流）**仍走新标签页**

## 四、实现规格

### 规格 A：新增「嵌入页面卡片」能力（首页）

**1. 新卡片类型：`embed-page`**
- `cardId`：`embed-page`（或按实例区分，见下）
- **关键设计**：嵌入页面是**多实例**的（领导可能嵌 2 个大屏），所以不能像 `ai-brief` 那样一个 cardId 一张卡。
  - **方案**：`cardId` 采用 `embed:<id>` 形式（如 `embed:dashboard-1`），或统一 `cardId: "embed-page"` + `params: {url, title}` 区分实例。
  - **请自行选择更契合现有布局引擎的实现**（注意：`applyOverride` 用 `cardId` 匹配，多实例需保证 cardId 唯一）。在实现摘要中说明选择理由。

**2. 渲染要求**
- **iframe 容器**：`<iframe src="..." sandbox="..." referrerpolicy="...">`，适配三栏中任意栏宽（含右栏 288px 与中栏全宽）
- **loading 态**：加载中显示骨架 + 「正在加载 XXX…」
- **失败降级**：超时（建议 8s）/被拒绝/加载失败 → 显示降级卡：页面标题 + 「无法在首页内嵌显示」+ 「**在新标签页打开**」按钮（走 #5 语义）+ 「重试」
- **卡片头部**：标题 + 「在新标签页打开」图标按钮 + （编辑模式下）「移除」
- **高度**：默认合理高度（如 320px），支持在编辑模式调整（可用栅格档位联动）

**3. 添加嵌入页面的入口**
- 在**首页编辑模式**下，提供「＋ 添加页面卡片」入口 → 弹窗填写：
  - **页面标题**（必填）
  - **页面 URL**（必填）
  - **高度**（可选，默认 320px）
  - **来源**：可从「已注册应用」中选一个（自动带出其 URL），或手动填 URL
- **白名单校验**：不在白名单的域名 → 提示「该域名未在应用注册中登记，需管理员先上架」（模拟校验即可，白名单可用 `MOCK.apps` + 若干预置域名）

**4. 预置演示数据（重要）**
- 请预置 1-2 个**能真实演示效果的**嵌入卡片示例，建议：
  - 「**经营驾驶舱**」（领导视角）—— 用**内联 SVG 或纯 CSS 绘制**一个模拟驾驶舱（KPI 数字 + 柱状/折线图 + 环形图），**不要依赖真实外部 URL**（原型零依赖）
  - 说明：原型环境下无法加载真实外部页面，所以内嵌内容用**本地模拟页面**演示（可用 `srcdoc` 或本地 HTML 片段）。**请在实现摘要中说明你如何解决"零依赖下演示 iframe"这个问题**——这是本次的技术难点。

### 规格 B：管理员按角色配模板（后台）

**升级既有 `PAGES.layouts`**（`pages-config.js`）：

**1. 模板列表增强**
- 现有：模板名称 / 适用角色 / 卡片数 / 状态 / 更新时间 / 操作
- **新增/增强**：
  - 「适用角色」列**支持多角色**（现在写的是"普通员工（486 人）"，可增强为标签形式展示多角色）
  - 新增「**布局版本**」标注（v1 24栅格 / v2 三栏），因 v2 已上线
  - **预置更贴合角色的模板**：建议至少含「**管理层首页**」（含经营驾驶舱嵌入卡片）、「普通员工首页」、「研发角色首页」——**让"按角色配模板"这个能力肉眼可见**

**2. 模板编辑器升级为 v2 三栏**
- 现有编辑器是**单画布 24 栅格**；需升级支持**三栏（左/中/右）**
- 物料面板需包含**嵌入页面卡片**类型（可添加并配置 URL/标题）
- 保留既有能力：拖拽/栅格调整/移除/查看 template_json/保存/发布（`highRisk`）
- **编辑嵌入卡片**：点击后能编辑其 URL、标题、高度

**3. 角色绑定与生效说明**
- 明确展示：**模板绑定角色 → 该角色用户首次登录即用此模板**；用户仍可个人微调（`user_override_json` 叠加）
- 可加一个「**按角色预览**」：选择角色 → 预览该角色看到的首页（含其专属嵌入卡片）

**4. 与布局引擎的一致性**
- 后台配的 `template_json` 必须与前端 `layoutTemplateV2` 结构**同构**（三栏 + cards + 嵌入卡片实例）
- 可复用 `MOCK.cardManifest` 作为物料来源

### 规格 C：移动端同步（重要约束）
- **移动端窄屏不适合嵌入大屏**。移动端策略：
  - **不渲染 iframe**（窄屏嵌入大屏会完全不可用）
  - 改为**「页面入口卡」**：显示标题 + 图标 + 「打开」→ 提示在新标签页/全屏打开（走 #5 语义）
  - 或：在移动端提供**全屏抽屉**展示（若技术上可行，自行判断）
- **请在实现摘要中说明移动端方案与理由**。

## 六、验收标准（用于判断是否成立）

1. **能添加任意页面**：编辑模式可添加一个嵌入卡片（填标题+URL），添加后立即在首页渲染
2. **能真实看到内容**：预置的「经营驾驶舱」卡片**能看到模拟的可视化内容**（不是白屏）
3. **失败有降级**：填一个无效/不可达 URL → 显示降级卡 + 「在新标签页打开」按钮，**不白屏**
4. **管理员能按角色配**：后台模板页能看出「不同角色有不同模板」，且「管理层首页」含嵌入卡片
5. **决议 #5 未被破坏**：应用图标点击仍走新标签页（未改成 iframe）
6. **不冲突**：新能力不影响既有功能（回归验证）
