## 三、本轮新需求：应用运营看板 + 能力使用总览

### 3.1 需求定义（主理人综合）

| # | 能力 | 说明 |
|---|---|---|
| 1 | **应用运营看板**（后台） | 应用调用量趋势 / 活跃应用排名 / 中台能力使用分布 / 异常下降告警 |
| 2 | **能力使用总览**（应用详情） | 「某应用用了中台哪些能力」一屏总览（SSO / 权限 / 待办 / 消息 / 文件 / 工作流 / 通知），每项标注**是否启用 + 使用量 + 接入时间** |
| 3 | **接入状态视图** | 七步 Checklist 的完成态（复用既有 checklist 数据） |

### 3.2 硬边界

1. **数据源复用 A1-F05 埋点通道**（`POST /v1/portal/behavior`），**不另起一套采集**——否则会出现"采集了没看板"或"看板要数据没采集"的错位
2. **不与 E2 审计混存**（沿用既有 D2 结论）
3. **脱敏与权限**：看板仅管理员可见；员工个人行为数据**不做跨人画像**（沿用 A1-F05 边界）
4. **无数据态**：埋点未就绪 / 数据不足时，看板显示明确引导（**不留空白图表**）

### 3.3 版本归属
**V1.5，与 A1-F05 埋点同批**（用户拍板）——理由：共用埋点通道，先有采集才有看板。
