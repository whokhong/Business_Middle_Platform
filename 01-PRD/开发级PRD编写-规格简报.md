## 五、评审层要求（专业产品视角）

**评审必须做且要有结论**，不得只列问题不修：

| 评审维度 | 检查什么 |
|---|---|
| **逻辑漏洞** | 输入/输出不闭环、状态机缺终态、权限漏洞（越权路径）、数据流断链 |
| **业务流程完整性** | 主流程 + 异常分支 + 回退路径是否齐全；跨域流程衔接是否有断点 |
| **需求关系冲突** | 功能点职责重叠/矛盾；依赖成环；边界表述不清 |
| **可开发性** | 是否可据此编码：字段/接口/状态/权限是否明确；有无"待定"影响开发 |
| **一致性** | 编号一致、术语一致、与 UIUX/详细设计口径一致 |

**输出**：评审报告（问题清单 + 严重级别 + 修复方案）→ **逐项修复** → 复评确认清零
